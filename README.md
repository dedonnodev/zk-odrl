# zk-odrl

Bachelor thesis prototype: prove with a zero-knowledge proof that you satisfy
an ODRL policy, without revealing your attributes, and verify the proof with a
Solidity contract.

Current state: hello world. The policy `policies/hello.json` has one
constraint, `level gteq 3`. Alice (`level` 4, private) gets a proof, Bob
(`level` 2) cannot generate one. The contract only sees the threshold 3.

## How it works

```
hello.json (ODRL) + alice.json
   └─ policy-input.js ──► {attribute: 4, threshold: 3}
                              └─ circuit (compiled by circom)
                                   └─ snarkjs + Groth16 ──► proof + ["3"]
                                                              └─ Groth16Verifier.sol on Hardhat (via viem) ──► true
```

- `scripts/policy-input.js` reads the policy and the user's attributes and
  writes the circuit input. It does not generate the circuit: the circuit
  (`circuits/policy.circom`, "attribute >= threshold") is the same for every
  threshold.
- circom compiles the circuit, snarkjs runs the Groth16 setup, makes the proof
  and exports the Solidity verifier.
- Hardhat runs a local EVM inside Node; viem deploys the verifier and calls
  `verifyProof`.

For Bob the chain stops at the circuit: 2 >= 3 is false, so there is no proof.

## Run

```bash
nix develop        # circom 2.2.3, node 22
npm ci             # snarkjs, circomlib, hardhat, viem (package-lock.json)
make hello         # proof for alice, checked by snarkjs and by the contract
make deny          # bob: no proof
make hello V=1     # same, with the full output of every tool
make clean
```

`make hello` checks three cases (real proof, wrong public input, modified
proof) with snarkjs and with the contract, and fails if any result is wrong.

## Limits

- The trusted setup uses a public beacon: anyone can forge proofs. Demo only.
- The contract is called with `eth_call` on the in-process Hardhat EVM, no
  transaction. The gas is an estimate for a whole transaction (21000 base
  included).
- Only one `gteq` constraint is supported.
